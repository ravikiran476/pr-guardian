PR Guardian
Checks Setup GitHub

Catch risky pull requests before review starts.

PR Guardian is a GitHub Action that checks every pull request for missing tests, leaked secrets, risky paths, coverage drops and lint errors. It posts one report comment and updates it on every push.

What it checks

Every finding is an error, warning or note. You choose which severity fails the run.

Missing tests

Each changed source file needs a matching test change. auth.ts pairs with auth.test.ts, auth_test.go or test_auth.py. Deleted tests are flagged.

Risky content

Scans only added lines for hardcoded secrets, AWS and private keys, .only tests, debugger and lint suppressions. You can add your own regex rules.

Protected paths

Blocks paths you list and flags workflows, migrations, Dockerfiles, Terraform and dependency manifests. Renamed files are checked under both names.

Coverage threshold

Fails below your minimum line coverage. Reads an istanbul coverage-summary.json or lcov.info from any language.

Lint limits

Enforces error and warning limits from an ESLint JSON report, counting only the files the PR touched.

PR size

Flags PRs over a file or line limit. Lockfiles, build output and snapshots don't count.

AI review summary

Optional. Claude summarizes what changed, the risks and its suggestions. It's advisory and never fails the run.

Setup

About two minutes. Nothing to host: the action runs inside your GitHub workflow.

  1. Add the workflow below as .github/workflows/pr-guardian.yml.
  2. Optional: add an ANTHROPIC_API_KEY repository secret for the AI summary.
  3. Open a pull request. The report shows up as a comment.
name: PR Guardian
on:
  pull_request:

permissions:
  contents: read
  pull-requests: write

jobs:
  guardian:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v5

      # Optional: produce reports for the coverage and lint checks.
      - run: npm ci && npx vitest run --coverage --coverage.reporter=json-summary
        continue-on-error: true

      - uses: ravikiran476/pr-guardian@v1
        with:
          coverage-file: coverage/coverage-summary.json
          ai-summary: true
          anthropic-api-key: ${{ secrets.ANTHROPIC_API_KEY }}

Configuration

Optional. Put a .github/pr-guardian.yml in your repo; any key you leave out uses its default.

size: { maxFiles: 50, maxLines: 1000 }

blockedPaths:
  - pattern: "config/production/**"
    reason: "managed by ops"

tests:
  sourcePatterns: ["src/**/*.ts"]
  severity: error   # block merges without tests

content:
  rules:
    - id: no-console
      pattern: "console\\.log\\("
      message: "Remove console.log"

coverage: { minimum: 85 }
lint: { maxErrors: 0, maxWarnings: 10 }
InputDefaultPurpose
fail-onerrorLowest severity that fails the run: error, warning, info or never.

commenttruePost the PR comment. The job summary is always written.
coverage-fileCoverage report from an earlier step.
lint-reportESLint JSON report from an earlier step.
ai-summaryfalseAdd the Claude review summary.
anthropic-api-keyNeeded for the AI summary.

Outputs errors, warnings and passed can drive later steps. PRs from forks don't get repository secrets, so the AI summary is skipped for them, with a note in the report. All other checks still run.
